# 模块五：客户管理 (Customers)

## 功能说明

客户是推送通知的最终接收方。一个客户可以关联多个通知渠道，同时客户也是订阅规则的指向对象。

客户弹窗的「持有产品 / 当前版本」与订阅规则使用同一套路径树，入口为「+ 添加产品」：点击后选中节点即确定产品与当前版本（如 `WAF V6.0.9`），升级包 / 列表等容器节点只用于继续展开。同一产品可添加多个不同版本（如 WAF 的 `V6.0.9` 与 `V6.0.8`）；弹窗支持一次多选，按 `产品 + 版本` 去重，同一产品的重复版本不会重复添加；已选路径以可删除标签展示（`产品@版本`，悬停显示完整路径）。编辑时兼容旧的 `"产品"` / `"产品:版本"` 字符串，以及不在当前采集目录中的历史产品。新建订阅规则选择客户后，订阅条件会默认沿用这里登记的产品与版本。

## 数据模型

### customers 表

```sql
CREATE TABLE customers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,              -- 客户简称（如"绿盟科技"）
    company TEXT DEFAULT '',         -- 公司全称
    contact TEXT DEFAULT '',        -- 联系人
    email TEXT DEFAULT '',          -- 通知邮箱
    phone TEXT DEFAULT '',          -- 联系电话
    owned_products TEXT DEFAULT '[]', -- JSON，拥有的产品及当前版本
    notes TEXT DEFAULT '',          -- 备注
    attachment_max_mb INTEGER DEFAULT 0, -- 附件大小限制（0=全局设置）
    created_by INTEGER REFERENCES users(id),
    created_at TEXT DEFAULT (datetime('now'))
)
```

## 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| name | TEXT | 客户名称（唯一标识，用于推送历史显示） |
| company | TEXT | 公司全称 |
| contact | TEXT | 联系人姓名 |
| email | TEXT | 默认通知邮箱 |
| phone | TEXT | 联系电话 |
| owned_products | TEXT(JSON) | 客户购买/拥有的产品及当前版本，`[{"product": "...", "version": "..."}]`；兼容旧 `"产品"` / `"产品:版本"` 字符串（读取时自动规整，不影响推送） |
| notes | TEXT | 备注信息 |

## 关联关系

客户与其他模块的关联：

```
customers
    │
    ├── subscription_rules.customer_id（一个客户可对应多条订阅规则）
    │
    ├── rule_channels.customer_id（订阅规则与渠道的绑定可关联客户）
    │
    └── delivery_log.customer_id（推送历史记录客户信息）
```

## API 设计

### GET /api/customers

列出所有客户。

**响应**：
```json
{
  "code": 0,
  "data": [
    {
      "id": 1,
      "name": "绿盟科技",
      "company": "绿盟科技股份有限公司",
      "contact": "张三",
      "email": "zhangsan@nsfocus.com",
      "phone": "13800138000",
      "owned_products": [
        {"product": "WEB应用防护系统(WAF)", "version": "V6.0.9"},
        {"product": "网络入侵防护系统(IPS)", "version": "5.6.11"}
      ],
      "notes": "VIP客户",
      "created_at": "2026-01-15T10:00:00"
    }
  ]
}
```

### GET /api/customers/push-summary

按客户聚合推送统计，供客户列表「推送 / 成功率（近30天）」列使用。

- `days` 可选，默认 `30`，`0` 表示全部历史。
- 返回 `items`：`id` / `name` / `total` / `success` / `failed` / `last_sent_at` / `last_product`，按推送总数倒序。
- 前端与客户列表并行请求；点击统计值跳转该客户的推送历史。

### GET /api/customers/:id/service-report

客户月度服务报告：把当月（按 UTC+8 划分边界）的 `delivery_log` 推送流水汇总，
供客户页「报告」按钮展示。

- `month=YYYY-MM` 可选，默认当前月；格式非法返回 `400`。
- `summary`：`total` / `success` / `failed` / `success_rate`（无推送时成功率为 `null`）。
- `deliveries`：最多 100 条，按发生时间倒序；时间优先取 `created_at`，为空时回退 `sent_at`；`truncated` 表示是否被截断。

```json
{
  "code": 0,
  "data": {
    "customer": {"id": 1, "name": "客户A", "company": "客户A有限公司"},
    "month": "2026-11",
    "month_label": "2026年11月",
    "summary": {"total": 3, "success": 2, "failed": 1, "success_rate": 66.7},
    "deliveries": [
      {"sent_at": "2026-11-10T03:00:00", "product_name": "WAF",
       "version": "V6.0R09F00", "package_type": "系统升级包", "status": "sent"}
    ],
    "truncated": false
  }
}
```

### POST /api/customers

创建客户。

**请求体**：
```json
{
  "name": "客户A",
  "company": "客户A有限公司",
  "contact": "李四",
  "email": "li@example.com",
  "phone": "13900001111",
  "owned_products": [
    {"product": "WEB应用防护系统(WAF)", "version": "V6.0.9"}
  ],
  "notes": ""
}
```

### PUT /api/customers/:id

更新客户信息。

### DELETE /api/customers/:id

删除客户。

**级联操作**：
1. 删除 `rule_channels` 中关联此客户的记录
2. 将 `subscription_rules.customer_id` 设为 NULL
3. 将 `delivery_log.customer_id` 设为 NULL（保留推送历史）
4. 删除 `customers` 记录

## 典型使用场景

### 场景：客户订阅特定产品的规则

1. 在「客户」中添加客户 A
2. 在「通知渠道」中添加企业微信渠道（绑定到客户 A）
3. 在「订阅规则」中创建规则：客户 A + WAF + 规则包
4. 当 WAF 有新规则包时，自动推送到客户 A 的企业微信
