## 1. 系统概述

绿盟升级监控平台用于监控 [update.nsfocus.com](https://update.nsfocus.com) 上 6 款安全产品（WAF / IPS / IDS / RSAS / NF / UTS）的升级包发布，发现新版本后通过企业微信/钉钉/飞书/邮件通知客户。

### 监控产品

| 产品 | 说明 |
|------|------|
| WAF | Web 应用防火墙 |
| IPS | 网络入侵防护系统 |
| IDS | 网络入侵检测系统 |
| RSAS | 远程安全评估系统 |
| NF | 下一代防火墙 |
| UTS | 统一威胁管理系统 |

### 通知渠道

| 渠道 | 用途 |
|------|------|
| 企业微信 | 机器人 Webhook 推送 |
| 钉钉 | 机器人 Webhook 推送 |
| 飞书 | 机器人 Webhook 推送 |
| 邮件 | SMTP 邮件（支持附件） |

### 采集模式

| 模式 | 频率 | 耗时 | 说明 |
|------|------|------|------|
| Quick 扫描 | 每4小时（可配置） | ~3-5分钟 | 增量扫描，检测页面变化 |

## 2. 快速入门

### 第一步：添加 Session

1. 登录 [update.nsfocus.com](https://update.nsfocus.com)
2. 按 F12 → Application → Cookies → 复制 `PHPSESSID` 的值
3. 在平台「Session 管理」粘贴并验证

### 第二步：添加通知渠道

在「通知渠道」页面添加至少一个渠道：
- **企业微信/钉钉/飞书**：填写机器人的 Webhook URL
- **邮件**：填写 SMTP 服务器信息、账号密码、收件人

### 第三步：添加客户

在「客户管理」页面添加需要接收通知的客户，填写名称、公司、邮箱等。

### 第四步：创建订阅规则

在「订阅规则」页面点击「+ 创建规则」，按向导分 4 步填写：
1. **基本信息**：规则名称、关联客户（自动带出客户邮箱与附件大小）、有效期
2. **订阅条件**：默认跟随客户档案的产品与当前版本，可手动增删路径，或勾选「订阅全部产品」
3. **推送策略**：即时 / 每周 / 每月 / 每季汇总、延迟天数、推送时间窗口、包回退通知
4. **通知对象**：机器人渠道用 `+` 逐个添加，添加后可选模板、可点 `×` 移除；邮箱用 `+`（或 Enter）逐个添加收件人，用 `+` 逐个添加发件渠道，按顺序主备（前一个失败自动用下一个），nsfocus.com / nsfocus.net 发件渠道会标记「优先」，确认摘要后保存

点击「下一步」会校验当前步骤；可点顶部步骤条回退修改，最后一步会显示客户、订阅条件、通知对象与推送模式的摘要。邮箱收件人留空时自动使用客户档案邮箱。

创建后系统自动开始监控，发现新包即时推送。

## 3. 仪表盘

系统首页，展示整体运行状态。

### 统计卡片

- **活跃 Session**：当前可用的 Cookie 数量
- **监控快照**：数据库中活跃的升级包快照总数
- **调度器**：当前状态（就绪 / 采集中）
- **今日推送**：今日推送总数 / 成功 / 失败
- **本周推送**：本周累计推送统计

### 采集状态

- **上次采集**：最近一次采集完成的时间（本地时间）
- **下次采集**：预计下次采集时间
- **手动采集按钮**：可手动触发 Quick 或 Full 扫描

### 最近推送

显示最近 N 天的推送明细，可按 1天/7天/30天/1年 筛选。

### 产品卡片

按产品分组显示最新的升级包概览。

### 包发布趋势图（左）

Canvas 多线折线图，展示近7/30/90天各产品每日发布包数量趋势。

- **图例切换**：点击产品标签可显示/隐藏对应曲线（斜体+删除线为隐藏）
- **悬停提示**：鼠标在图表上移动显示垂直参考线+当天各产品数值气泡
- **时间范围**：通过图表下方或右侧的 7天/30天/90天 按钮切换

### 产品发布分布（右）

表格展示近N天各产品发布包数量及占比。

- 按数量降序排列
- 每行显示：产品名称、包子、占比进度条
- 通过右侧 7天/30天/90天 按钮切换时间范围

## 4. Session 管理

绿盟站点需要登录才能访问升级包详情。PHPSESSID 有过期时间（约24分钟无操作），系统每30分钟自动发送心跳保活。

### 操作

| 操作 | 说明 |
|------|------|
| 添加 | 粘贴 PHPSESSID，系统自动验证有效性 |
| 验证 | 手动验证 Session 是否有效 |
| 修改类型 | 点击类型标签切换采集/发现与标品/虚拟化；把最后一个采集 Session 改为发现时会警告「将无法采集数据」，需再次确认 |
| 删除 | 删除失效的 Session；删除最后一个可用的采集 Session 时会额外警告「将无法采集数据」，需再次确认 |
| 心跳历史 | 查看 Session 心跳记录（成功/失败/延迟） |

## 5. 通知渠道

### 添加渠道

**IM 渠道（企微/钉钉/飞书）**：
- Webhook URL：机器人的完整 Webhook 地址
- Secret（可选）：签名密钥

**邮件渠道**：
- SMTP 服务器地址和端口
- 用户名和密码（授权码，非登录密码）
- 发件人名称
- 收件人列表（逗号分隔）
- **每小时/每天发送上限**（0=不限制，可选配置，防止单渠道被异常流量打满）

### 邮件频率限制

为防止 Bug 导致邮件轰炸，系统对所有邮件发送实施三层限流：

| 层级 | 配置位置 | 默认值 | 超限行为 |
|------|---------|--------|---------|
| 渠道级 | 渠道编辑页（每个SMTP独立） | 0=不限制 | 跳过该渠道，规则内其他渠道仍可用 |
| 客户级 | 系统配置页 | 10封/时，50封/天 | 跳过该客户本次通知 |
| 全局级 | 系统配置页 | 100封/时，500封/天 | 停止所有邮件发送 |

> 超限时写 WARNING 日志，DeliveryResult 标记为失败并记录原因。计数器 DB 持久化，服务重启不丢。

### 安全说明

编辑已有渠道时，Webhook URL 中的 `key` 参数会被掩码显示（`key=********`），SMTP 密码和 Secret 不显示。留空不修改则保留原值。

### 测试

每个渠道都有「测试」按钮，可发送一条测试消息验证连通性。

### 支持邮箱

| 邮箱 | SMTP | 端口 | 说明 |
|------|------|------|------|
| QQ邮箱 | smtp.qq.com | 465 | 需开启SMTP服务，使用授权码 |
| 163邮箱 | smtp.163.com | 465 | 需开启SMTP服务 |
| 126邮箱 | smtp.126.com | 465 | 需开启SMTP服务 |

## 6. 客户管理

### 客户信息

| 字段 | 说明 |
|------|------|
| 名称 | 客户名称（必填） |
| 公司 | 公司名称（必填） |
| 邮箱 | 联系邮箱（必填） |
| 电话 | 联系电话 |
| 持有产品 / 当前版本 | 客户购买的产品及在用的产品版本（版本可选，如 `V6.0.9`） |
| 附件限制 | 单封邮件附件大小上限（MB，0 表示使用全局设置） |

### 使用说明

- 「持有产品 / 当前版本」用于生成资产台账：点「+ 添加产品」打开与订阅规则相同的路径树，可一次多选多个节点；选中节点即确定产品与当前版本（如 `WAF V6.0.9`），升级包/列表等容器节点只用于继续展开。同一产品可添加多个不同版本，按 `产品@版本` 去重；已选路径以 `产品@版本` 标签展示，点标签上的 × 可移除。新建订阅规则时默认沿用这里登记的产品与版本
- 客户列表每行的「报告」按钮打开月度服务报告：可切换上月/下月，查看当月推送明细（时间/产品/版本/类型/状态）与推送成功率；月份按北京时间划分
- 客户列表的「推送 / 成功率（近30天）」列显示该客户近 30 天推送总次数与成功率；有失败时标橙/红，0 推送显示「近30天无推送」，点击统计值进入该客户的推送历史
- 通知正文只展示规则包新增/修改/删除的条数摘要；规则库变更详情（规则名列表）暂不接入推送
- 客户邮箱会作为推送时的默认收件人
- 可在订阅规则中覆盖客户邮箱

## 7. 订阅规则

订阅规则是系统的核心——决定**什么产品的新包**通过**哪些渠道**通知**哪个客户**。

### 规则列表

| 列 | 说明 |
|----|------|
| 📢 | 回退通知开关图标 |
| 名称 | 规则名称 |
| 客户 / 收件人 | 关联客户名称及邮箱 |
| 通知对象 | 实际接收通知的目标，优先取规则级客户邮箱，机器人渠道则显示「名称(类型)」 |
| 订阅条件 | 订阅的产品/版本/类型条件，「📡 全部产品」表示监控全部 |
| 命中 / 最近（近30天） | 近 30 天匹配到的去重包数与最近命中时间；「未命中」标黄，提示规则可能无效，点击进入该规则推送历史 |
| 推送 | 即时 / 每周 / 每月 / 每季 |
| 有效期 | 规则有效期 |
| 状态 | 启用/停用（点击切换） |

### 创建/编辑规则

| 字段 | 说明 | 必填 |
|------|------|------|
| 规则名称 | 便于识别的名称 | ✅ |
| 📡 订阅全部产品与类型 | 勾选后不设筛选条件，监控所有产品的全部升级包 | |
| 关联客户 | 从客户列表选择 | ✅ |
| 客户邮箱 | 覆盖客户档案邮箱，多个逗号分隔 | |
| 订阅条件 | 产品+版本+类型，可添加多组（勾选「全部」后隐藏） | |
| 延迟(天) | 发现后延迟N天推送，0=立即推送 | |
| 推送模式 | 即时/每日汇总/每周汇总/每月汇总 | |
| 有效期至 | 规则失效日期 | |
| 通知渠道 | 可添加多个渠道 | |
| 附件大小(MB) | 0=使用全局设置 | |
| 回退通知 | 是否通知包撤回 | |

新建规则选择关联客户后，订阅条件默认按客户档案的「持有产品 / 当前版本」自动填入对应路径（同一产品落到已登记的版本分支）。手动调整过路径或勾选「全部产品」后不再自动覆盖；编辑已有规则保留原条件。「添加路径」弹窗会带上当前已选路径，取消不会清空。

### 📡 订阅全部产品与类型

勾选此选项后：
- 订阅条件选择区自动隐藏
- 规则会匹配**所有 6 个产品**的**全部类型**升级包
- 列表显示蓝色「📡 全部产品」标识
- 相当于 `filter_conditions = {}`，后端空条件默认匹配全部

### 删除保护

- 删除客户前检查是否被订阅规则引用，有引用则拒绝并提示规则名
- 删除渠道前同样检查引用关系
- 需先在订阅规则中取消关联后再删除

### 通知渠道说明

> **重要**：系统只通过规则中勾选的渠道发送通知。关联客户有邮箱 ≠ 自动发邮件，必须显式勾选邮件渠道才会发送邮件。

### 延迟推送策略

| 策略 | 行为 |
|------|------|
| 重置 | 每次新包重新计时，延迟窗口内只发一次 |
| 追加 | 延迟窗口内新包追加到同一批次 |
| 窗口 | 固定时间窗口推送 |

### 汇总模式

| 模式 | 行为 |
|------|------|
| 即时 | 新包立即推送 |
| 每周 | 每周指定日期合并推送一次 |
| 每月 | 每月指定日期合并推送一次 |
| 每季 | 每季度合并推送一次 |

汇总消息可直接发往规则绑定的邮箱渠道：收件人沿用规则 / 客户档案邮箱（并按顺序主备），正文以 HTML 邮件发送；企微 / 钉钉 / 飞书长消息仍自动分片。

## 8. 数据采集

展示当前监控的所有升级包快照。

### 页面功能

| 功能 | 说明 |
|------|------|
| 产品分组 | 按产品分组，可折叠/展开 |
| 版本分组 | 按版本分支分组 |
| 包详情 | 点击行展开查看完整信息（含页面HASH：旧hash→新hash） |
| **推送按钮** | 手动推送某个包（按客户/渠道/手动邮箱） |
| **推送频率限制** | 同邮箱/渠道 1分钟最多5次，超限10分钟禁用 |

### 推送模态框

点击包行的「推送」按钮，三种模式：

1. **👤 按客户**（默认）：选择有邮箱的客户，系统自动通过邮件渠道中继发送到客户邮箱
2. **📡 按通知渠道**：选择单个渠道直接推送（email渠道使用其配置的收件人）
3. **✉️ 手动填写邮箱**：直接输入邮箱地址，多个用逗号分隔，实时格式校验

> **注意**：手动推送忽略客户订阅的产品/版本限制，直接发送当前快照内容。

### 推送频率限制

防止恶意利用手动推送功能：

| 规则 | 说明 |
|------|------|
| 频率上限 | 同一邮箱或渠道 1 分钟内最多 5 次推送 |
| 超限处罚 | 超过后该邮箱/渠道推送功能禁用 10 分钟 |
| 恢复方式 | 10 分钟后自动恢复，或管理员通过 API 手动重置 |
| 重置 API | `POST /api/system/rate-limits/reset` `{"key":"email@x.com"}` 或 `{}` 全部 |

超限时前端按钮显示倒计时「已禁用 M:SS」，到时自动恢复可点击。

| 列 | 说明 |
|----|------|
| 类型 | 包类型（中文） |
| 文件 | 文件名 |
| 发布时间 | 绿盟发布该包的时间 |
| 最近采集 | 系统最近一次确认该包仍在线的时间 |
| 大小 | 文件大小 |
| 紧急度 | normal/high/critical |

## 10. 系统配置

> 页面按分区卡片双列排布（窄屏自动单列），每个分区标题右侧标注生效时机；修改完成后点击页头右上角「保存配置」，采集中则显示「强制停止并保存」。

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| **🔧 维护模式** | 关闭 | 开启后所有推送静默，采集照常 |
| 采集间隔 | 4 小时 | Quick 扫描间隔 |
| 速率下限 | 1.0 秒 | HTTP 请求最小间隔 |
| 速率上限 | 3.0 秒 | HTTP 请求最大间隔（随机） |
| 附件上限 | 10 MB | 邮件附件最大大小（全局） |
| 自动备份间隔 | 30 天 | 每天 03:30 检查，距上次备份超过 N 天才生成新备份 |
| 保留份数 | 6 | 超出自动删最旧；调小并保存立即清理多余备份，页面显示当前总占用 |
| 快照保留 | 180 天 | 超过后自动清理 |
| 静默开始 | 22:00 | 静默时段开始 |
| 静默结束 | 08:00 | 静默时段结束 |
| 采集间隔 | 4 小时（可配置） | Quick 扫描间隔 |
| 心跳间隔 | 30 分钟 | Session 保活间隔 |

### 📧 邮件频率限制

防止 Bug 导致邮件轰炸的硬上限配置：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 全局-每小时上限 | 100 | 整个系统每小时最多发N封，0=不限制 |
| 全局-每天上限 | 500 | 整个系统每天最多发N封 |
| 客户-每小时上限 | 10 | 每个客户独立计数，每小时最多N封 |
| 客户-每天上限 | 50 | 每个客户独立计数，每天最多N封 |

> 渠道级别的限制在「通知渠道」编辑页单独配置，优先级：渠道 > 客户 > 全局

### 维护模式

开启后：
- 采集照常运行
- 所有推送静默（即时/延时/手动/摘要）
- 适合调试和测试环境

### 包分类配置

可配置哪些包类型属于「全量包」（离线升级包），用于摘要汇总时去重。

## 11. 仪表盘

主导航 **「仪表盘」** 把 `/api/metrics` 的指标直接画在页面上，用于判断推送链路和采集是否健康。

| 分区 | 看什么 |
|------|--------|
| 顶部 KPI | 调度器、未确认告警、推送、成功率、产品更新、待投递队列、活跃 Session；推送 / 成功率跟随右上角时间筛选，调度器关闭时整张卡转红并在页顶告警 |
| 投递成功率 | 按渠道统计总数 / 成功 / 失败 / 待定，失败数标红；成功率低于 95% 进度条转橙、低于 80% 转红 |
| 产品更新 | 窗口内按产品大类聚合的更新包数与最近更新时间，跟随右上角时间筛选 |
| 队列积压 | 即时队列的待处理 / 逾期 / 重试中 / 最久等待；汇总队列按规则列出待发数 |
| 调度任务 | 紧跟顶部 KPI 之后；列出采集、心跳、汇总、投递队列、清理、渠道体检、站点可用性、数据库备份、数据库健康的下次运行时间与倒计时；绿点运行 / 红点停止 / 灰点未启用 |
| 站点可用性 | 定期探测 `update.nsfocus.com` 的 HTTP 状态、响应耗时、上次检测、连续失败次数与最近可用时间；延时曲线带毫秒 Y 轴与起止时间，红色虚线表示不可用时刻；下方「状态变化」列出最近几次 UP / DOWN 的起止时间与持续时长（当前状态显示「至今」）。与左侧调度任务卡片保持等高 |
| 采集健康 | 调度器与维护模式状态、上次/下次采集、上次与近 20 轮平均耗时、数据源是否有超过 24h 未更新 |
| 客户推送 | 按客户统计窗口内推送总数与成功率，点击客户行下钻推送历史 |
| 事件与告警 | 窗口内各严重级别事件数，以及未确认（未读且未解决）的 CRITICAL / ERROR / WARNING；点击数字弹窗查看。完整列表在主导航「事件与日志」页，可按严重度 / 时间范围 / 状态筛选，单条「已读」或「解决」，也可按当前筛选批量确认 / 批量解决 |
| 存储与数据量 | 数据库文件大小、快照数、投递日志 / 汇总队列 / 系统事件行数 |

页面默认统计最近 24 小时，可切换 6 小时 / 7 天 / 30 天，每 30 秒自动刷新一次；投递、产品更新、事件与客户推送都跟随该窗口。切到其他页面或退出登录后自动停止刷新。

Prometheus 抓取地址与接入说明在「系统配置 → 🔌 外部观测接入」中查看与复制。服务端配置 `MONITOR_METRICS_TOKEN` 后，Prometheus 使用 `Authorization: Bearer <token>` 或 `X-Metrics-Token` 即可长期抓取；页面本身不会展示该令牌。详细口径与抓取配置见 `docs/modules/11-可观测性.md`。

> 提示：队列「逾期」不等于故障，静默时段、订阅时间窗、渠道临时异常都会让 `push_after` 到期后继续等待；关注的是逾期数是否持续增长。

### 事件与日志页

主导航 **「事件与日志」** 把告警与运行日志放在同一入口：一个页面标题，右上角分段开关直接切换两种视图（不再有两个大页签）：

| 视图 | 用途 |
|------|------|
| 🔔 事件与告警 | 按严重度 / 时间范围（6 小时 ~ 全部时间）/ 状态（未读 / 已读未解决 / 已解决）筛选；点击行展开详情（含失败投递的「重新入队」）；单条「已读」或「解决」；「批量确认」只标记当前筛选范围内未读的事件，「批量解决」只标记当前筛选范围内未解决的事件。站点恢复、数据库锁恢复会自动解决对应事件 |
| 📋 系统日志 | 选择日志文件、级别与行数查看 app.log / access.log，可开启自动刷新或临时开启 DEBUG 级别 |

仪表盘「事件与告警」卡片仍可点数字弹窗快速查看，弹窗与本页共用同一套筛选和批量操作逻辑。已解决事件保留 180 天，未解决告警保留 365 天，由每日 03:00 的数据库清理任务处理。

## 13. 常见问题

### Q: 为什么仪表盘时间比实际少8小时？
A: 已修复。数据库统一存 UTC，页面与业务边界（静默期、推送窗口、汇总周期、月度报告）统一按 UTC+8 计算和展示，不依赖服务器或浏览器时区设置。

### Q: 为什么 Quick 扫描没有发现新包？
A: Quick 扫描需要先运行一次来填充 `source_url`。首次部署会自动触发。之后按配置的间隔检测已知页面变化。

### Q: 邮件发送失败？
A: 检查：
1. QQ邮箱需用授权码非登录密码
2. 云服务器 IP 可能被网易邮箱风控，建议用 QQ 邮箱
3. 端口 465 使用 SSL，25/587 使用 STARTTLS

### Q: 如何不让某客户收到撤回通知？
A: 编辑该规则，取消勾选「📢 包回退通知」。

### Q: 如何临时关闭所有推送？
A: 系统配置 → 开启「🔧 维护模式」。

### Q: 推送被频率限制了怎么恢复？
A: 两种方式：
1. 等待 10 分钟自动恢复
2. 管理员调用 API 立即重置：
```bash
# 重置某个邮箱
curl -u admin:<your_password> -X POST http://127.0.0.1:9999/api/system/rate-limits/reset \
  -H 'Content-Type: application/json' -d '{"key":"user@example.com"}'
# 重置全部
curl -u admin:<your_password> -X POST http://127.0.0.1:9999/api/system/rate-limits/reset \
  -H 'Content-Type: application/json' -d '{}'
```
A: 使用天数筛选（默认30天），或点击「清空」按钮清理旧记录。

### Q: Channel 密码会被泄露吗？
A: 编辑渠道时 webhook key 显示为 `********`，密码不显示。留空不修改保留原值。
